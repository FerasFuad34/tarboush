## 3) قياس دقة التفريغ (WER) — أرقام حقيقية

**الملف المرجعي:** تسجيل اصطناعي 44.9 ثانية بالعربية الفصحى (نص مرجعي 60 كلمة)، بمحتوى محاضرة فيزياء.
**الأداة:** `backend/tests/wer_tool.py` (تطبيع عربي: تشكيل/ألف/تاء مربوطة/ترقيم، ثم Levenshtein على الكلمات).

| النموذج | التلميح | WER | أخطاء/كلمات | الزمن على CPU |
| :--- | :---: | ---: | :---: | ---: |
| tiny | عام | 84.6% | — | 15s |
| base | عام | 46.67% | 28/60 | 5.3s |
| small | عام | 23.33% | 14/60 | 19.5s |
| **small** | **مصطلحات المادة** | **11.67%** | **7/60** | **14.0s** |
| medium | — | لم يُكمل | — | تجاوز ذاكرة الحاوية (1GB) — متوقع أن يعمل على جهازك بذاكرة 8GB+ |

**استنتاجات صريحة:**
1. تلميح المصطلحات (Hotwords) **يخفض WER بنسبة النصف تقريباً** (21.7% → 11.7%). لذلك صار عنوان المحاضرة يُمرَّر تلقائياً كتلميح في كل عملية تفريغ.
2. الرقم أعلاه على **كلام اصطناعي واضح**، وليس على تسجيل قاعة حقيقي بلهجة يمنية. الأرقام على تسجيل حقيقي ستكون أعلى، ولا يصح الادعاء بغير ذلك.
3. لم نستطع قياس ملف 60 دقيقة داخل بيئة الاختبار (ذاكرة محدودة)؛ السرعة المقاسة **≈ 0.31× من الزمن الحقيقي** بـ small على CPU (45 ثانية صوت → 14 ثانية معالجة). أي أن محاضرة 30 دقيقة ≈ **9–15 دقيقة معالجة** على CPU مشابه.
4. تحسين M2 المقترح: تصحيح لاحق بـ LLM مقيّد + مقارنة مع Groq.

## 5) ما الذي تغيّر بعد الاختبار (أخطاء اكتُشفت وأُصلحت فعلياً)

| المشكلة التي ظهرت في التشغيل | الإصلاح |
| :--- | :--- |
| `ModuleNotFoundError: celery` كان يُسقط طلب الرفع كاملاً | فصل خط المعالجة في `pipeline.py` مستقل عن Celery + دالة `dispatch_processing` |
| رسالة PDF تالف تحتوي تفاصيل تقنية إنجليزية | رسائل عربية بحتة لكل نوع ملف |
| شارة حالة النظام تظهر «-» | `/health` يرجّع `{ok,label,detail}` والواجهة تبني الشارات منها |
| PDF عربي يظهر بمربعات (خط Helvetica) | تضمين `NotoNaskhArabic` + إصلاح مسار الخطوط |
| خطأ فوري: `'LLMService' object has no attribute 'generate_quiz'` | إعادة الدالة المفقودة + التحقق من صحة الحقل لكل سؤال |
| صفحة المحاضرة تعرض `done 100%` بدل العربية | قاموس حالات عربي (`مكتملة/جاري التلخيص/فشلت/...`) |
| بطاقة «حالة النظام» كانت فارغة (طلب خارج مسار الـ proxy) | إضافة بروكسي `/health` في Vite و Nginx |
| أي خطأ 404 كان يتحول إلى 500 | معالج `HTTPException` مخصص |
| المشغل الصوتي كان في تبويب التصدير فقط | نقله إلى شريط ثابت يظهر مع كل التبويبات |
| تجمّد المعالجة إن كان Ollama مغلقاً | مهلة اتصال 3 ثوانٍ ومهلة قراءة 180 ثانية |

## 7) القيود المعروفة الآن (بصراحة)

1. **لا حساب مستخدم فعلي بعد** — M1 يستخدم مستخدماً افتراضياً واحداً. تعدد المستخدمين في M4.
2. **لا تصدير PDF عبر المتصفح مباشرة** — الروابط تعمل كتنزيل (GET)، وهو سلوك مقصود.
3. **جودة OCR تعتمد على وضوح الصورة** — النموذج لا يصحح أخطاء مسح رديء.
4. **بدون Ollama** تكون الملخصات استخراجية (جمل حرفية) لا توليدية — وهذا معلن في الواجهة عبر شارة الحالة.
5. **محاضرة 3 ساعات** لم تُختبر داخل بيئة التطوير (ذاكرة 1GB)؛ الحد العملي المختبر 45 ثانية صوت وملفات نصية. تقسيم الملفات الطويلة إلى أجزاء متوازية مؤجل إلى M3.
6. **لا رفع مستأنف** للملفات الكبيرة (1GB) بعد.
